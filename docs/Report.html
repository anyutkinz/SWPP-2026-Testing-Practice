3. Specifications

dueDateLabel(dueDate: LocalDate?, today: LocalDate, isCompleted: Boolean): String is a pure function: completed → "CLEAR"; active without a due date → "" (the "no label" value: its KDoc documents "Active task with no due date: "" (nothing is shown)", matching the intended behaviour "active with no due date: no label" on slide 53); otherwise "D-N", "D-Day" or "D+N", where N is the total number of calendar days. All its post-conditions are [Unit].

setDueDateLabel(textView: TextView, task: Task?) reads LocalDate.now() itself and writes the label into a TextView. It needs the Android runtime (the project has no Robolectric), so all its post-conditions are [Integration]. "Shows X" means exact text X and View.VISIBLE; "shows no label" means textView.text.toString().isEmpty() || textView.visibility != View.VISIBLE (option (a), chosen by the student; neither the KDoc nor the assignment requires a stronger "empty and GONE" contract). A visible stale CLEAR therefore fails.

Final specs: 34 Tips for dueDateLabel() (AI draft: 31) and 16 Tips for setDueDateLabel() (AI draft: 16). Neither spec uses Tested by, because no pre-existing test checked these functions; the template structure is unchanged.

7.1 Bug 1 — the count uses only the days component of java.time.Period

Intended: N is the total number of calendar days between today and dueDate (slide 53; PR: "N counts calendar days"). Why these tests, and why others pass. A test can expose this bug only if the interval has a non-zero months or years component. That is why the 30-day case passes (period 30 days) while the 31-day case fails (period exactly 1 month → D-Day), and the 32-day case fails as D-1. Short calendar-boundary cases (month end, year end, leap day, ±1 day) pass on the buggy code: they check boundary correctness but cannot tell total days from the days component of java.time.Period. The binding-level 42-day test exposes the bug on any run date, because 42 days always contain at least one whole month.

7.2 Bug 2 — a stale label is not cleared

Intended: an active task without a due date shows no label, and the label updates when the task is checked or unchecked (slide 53). Observed cause: setDueDateLabel writes text and VISIBLE only if (label.isNotEmpty()). For an empty label it does nothing, so whatever an earlier binding showed in the same view stays. Representative test: TasksListBindingsTest.setDueDateLabel_noDueDateTaskCheckedThenUnchecked_showsClearThenNoLabel. On one TextView it binds Task("Task", isCompleted=false, dueDate=null, id="t1"), then copy(isCompleted=true), then copy(isCompleted=false). After the check it shows CLEAR (pass); after the uncheck it expects no label, but the view still shows CLEAR and is VISIBLE.
